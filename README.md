## 🤔 어떤 도구인가요?

카카오톡에서 AI에게 질문하고 싶을 때 쓰는 작은 연결 프로그램입니다.
자신의 카카오 계정으로 로그인하고, 사용할 AI와 응답할 대화방을 직접 지정합니다.

```text
허용한 카카오 대화방 → 카카오 AI 브리지 → 내가 설정한 AI
                    ← 같은 방에 답변 ←
```

- 🔗 **AI 선택**: OpenAI 호환 Chat Completions API 또는 본인이 운영하는 호환 게이트웨이에 연결합니다.
- 🚪 **방 직접 선택**: 설정하지 않으면 모든 방을 차단합니다. 전체 방 자동 허용은 없습니다.
- 🙋 **명시적인 질문만**: 다른 참가자가 `!ai 질문`으로 호출한 메시지만 처리합니다.
- 🧹 **대화 기억 없음**: 질문 한 건씩 전달하며, 이전 대화나 다른 방의 기록을 붙이지 않습니다.

별도 웹 화면이나 카카오 공식 챗봇 관리 페이지는 없습니다. **자신의 컴퓨터 또는 서버에서 터미널로 실행하는 도구**입니다. AI 서비스 사용료와 서버 비용은 이용하는 서비스에 따라 발생할 수 있습니다.

## 💬 이렇게 사용해요

설정을 마친 뒤, 허용한 방에서 **봇 계정이 아닌 다른 참가자**가 다음처럼 보냅니다.

```text
!ai 이 문장을 더 쉽게 풀어 써 줘: 토양 유기물은 다양한 기능을 한다.
```

브리지가 질문을 설정한 AI에 전달하고, 받은 답을 같은 방에 보냅니다.
접두사 `!ai` 뒤에는 공백이 필요합니다. 봇 자신의 메시지에는 답하지 않습니다.

> 💡 검색·최신 뉴스·일정 등록은 이 프로그램의 기본 기능이 아닙니다. 연결한 AI 서버의 기능과 권한에 따라 달라집니다.

## 🛠️ 직접 실행해 보기

### ⚙️ 먼저 준비해 주세요

- **Node.js 22.13 이상 24.x 이하**와 npm — 22.x 또는 24.x LTS 권장
- Linux 또는 macOS 환경 — Linux 검증 완료, macOS 실기기 미검증
- 본인 소유의 테스트용 카카오 계정과 휴대폰 인증 수단
- 사용할 AI의 API 주소·키·모델 이름

Windows는 WSL의 Linux 파일시스템을 사용하세요. 네이티브 Windows는 지원하지 않습니다. root가 아닌 전용 일반 사용자로 실행하세요.

### 📥 1. 내려받고 설정 파일 만들기

```sh
git clone https://github.com/Dj-Lee2/kakao-ai-bridge.git
cd kakao-ai-bridge
npm ci --ignore-scripts --omit=optional
npm run setup
```

`setup`은 `.env.example`을 바탕으로 나만의 `.env`를 만듭니다. 기존 설정은 덮어쓰지 않습니다.

### 🔗 2. 사용할 AI 연결하기

`.env`를 열어 자신의 값으로 채웁니다.

```dotenv
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=
AI_MODEL=
KAKAO_ALLOWED_ROOMS=
KAKAO_TRIGGER_PREFIX=!ai
```

- `AI_BASE_URL`: API 기본 주소입니다. `/chat/completions`는 프로그램이 붙입니다.
- `AI_API_KEY`·`AI_MODEL`: 이용하는 서비스에서 확인한 키와 모델 이름을 넣습니다.
- `KAKAO_ALLOWED_ROOMS`: 다음 단계에서 조회한 방 ID를 넣습니다. 비워 두면 실행이 차단됩니다.

**카카오 이메일과 비밀번호는 `.env`에 넣지 않습니다.** 본인 OpenClaw 게이트웨이 연결 예시는 [상세 안내](docs/GUIDE.md)에 있습니다.

### 📱 3. 카카오 로그인과 방 선택

화면 공유·터미널 녹화를 끈 상태에서 실행하세요.

```sh
npm run login
npm run rooms
```

로그인 명령에서 이메일·비밀번호를 숨김 입력하고 휴대폰 인증을 진행합니다. 비밀번호는 저장하지 않습니다. 방 목록은 본인이 확인한 후 조회하며, 이 목록도 외부에 공유하지 마세요.

조회한 방 ID를 `.env`의 `KAKAO_ALLOWED_ROOMS`에 입력합니다. 여러 방이면 쉼표로 구분하고 공백은 넣지 않습니다. 방 참가자에게 AI 전송 사실을 알리고 동의를 받으세요.

### ▶️ 4. 확인하고 시작

```sh
npm run doctor
npm start
```

`doctor`는 **로컬 설정 검사**이며 실제 로그인·AI 연결 성공을 보장하지 않습니다. `ready` 이벤트가 나온 뒤 허용한 방에서 다른 참가자 계정으로 호출합니다. 종료는 `Ctrl+C`입니다.

인증 실패·기기 슬롯 점유·방 목록 누락 등은 [설치와 문제 해결 안내](docs/GUIDE.md)를 확인하세요. 추가 인증이나 계정 제한을 우회하지 마세요.

## 🔒 개인정보는 어떻게 다루나요?

- 🙅 저장소에는 실제 이메일·비밀번호·토큰·방 목록·대화 기록을 넣지 않습니다.
- 📁 개인 설정은 `.env`, 로그인 세션과 동기화 상태는 기본 `.state/`에 저장하고 Git에서 제외합니다.
- 🔐 세션 파일은 소유자 전용 권한으로 제한합니다. **암호화 저장은 아니므로** 같은 OS 사용자나 관리자는 읽을 수 있습니다.
- 💬 유효한 질문 한 건과 고정 안내문만 AI로 전송합니다. 방 이름·카카오 ID·이전 대화는 AI 요청에 넣지 않습니다.
- 🗂️ SDK는 연결 과정에서 계정 전체의 초기 채팅 메타데이터를 받을 수 있습니다. 허용목록은 **AI 전달·응답 범위**를 제한하는 장치입니다.
- 🛡️ 연결한 AI 서버의 파일·셸·외부 서비스 권한은 이 브리지가 차단하지 못합니다. 개인 관리자용 서버가 아닌 **별도 최소권한 AI**를 연결하세요.

질문은 선택한 AI 서비스로 전송되므로 해당 서비스의 보관·학습 정책도 확인해야 합니다. 비밀정보나 민감한 개인정보는 보내지 마세요. 상태 폴더를 변경할 때의 제외 규칙 등은 [상세 안내](docs/GUIDE.md)에 정리했습니다.

## 📦 어디까지 들어 있나요?

**포함되어 있어요**
- 최초 로그인·방 조회·설정 진단·실행 명령
- 명시적 방·발신자 검증과 질문량 제한
- 중복 처리 억제, 단일 발송 시도와 결과 재조회
- 한글 안내·예시 설정·고정 의존성·GitHub/GitLab 테스트 설정

**아직 포함하지 않아요**
- Zoom·팀 업무 명령·일정·예약 뉴스·자동 공지
- 장기 기억·이미지·음성·첨부파일 처리
- 자동 재접속·누락 메시지 복구·자동 재발송
- Docker 설치·서버 자동 배포·사용자용 웹 화면

전송 결과가 불확실하면 중복 발송을 피하기 위해 멈춥니다. 장애 시 질문이 누락될 수 있으며, 정확히 한 번 전달되는 것을 보장하지 않습니다.

## ✅ 무엇을 확인했나요?

초기 배포 후보를 ZIP에서 새 폴더로 풀고, 분리된 사용자 환경에서 확인했습니다.

- Node.js 22·24에서 **각각 41개 테스트 통과**
- 별도 안전성 회귀 검사 8개 통과 — 같은 검사는 저장소 테스트에도 포함
- 실제 터미널의 숨김 입력·취소 동작 확인
- 새 설치·기존 설정 보존·미설정 차단·Git 제외 규칙 확인
- 소스 ZIP 무결성과 개인정보 패턴 검사

테스트는 실제 고정 SDK와 모의 HTTP·전송 계층을 사용합니다. **실제 카카오 로그인·메시지 송수신 테스트가 아닙니다.** 보안 경고가 해결되었다는 뜻도 아닙니다.
